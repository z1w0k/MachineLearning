# Поиск объявлений услуг

Решение в `two_towers_retrieval.ipynb`. Для каждого запроса оно выбирает 50 объявлений из `benchmark_items.parquet` и записывает их в `answer.csv`.

## Как устроена модель

Для текста используется `intfloat/multilingual-e5-small`. Запрос объединяется с фильтрами, объявление — с заголовком, параметрами и описанием. E5 не дообучается: её векторы сохраняются на диск.

Дальше работают две отдельные небольшие сети: одна для запроса, другая для объявления. Они учатся сближать правильные пары и отдалять остальные. Несколько известных правильных объявлений одного запроса учитываются вместе.

При поиске сравниваются нормализованные векторы. Для итогового корпуса строится HNSW. Числовые признаки и география в модель не входят.

## Запуск

На Mac открой ноутбук и выполняй ячейки сверху вниз. Файлы должны лежать в `avito_retrieval/data` внутри папки `soso`:

- `train.parquet`
- `benchmark_queries.parquet`
- `benchmark_items.parquet`

В Colab включи GPU и выполни первую ячейку подключения Диска, убрав комментарии. Папка `avito_retrieval` может лежать прямо в «Моём диске» или внутри `soso`.

Библиотеки устанавливаются во второй кодовой ячейке. На Mac код использует MPS, в Colab — CUDA, если ускоритель доступен.

Кодирование текстов занимает больше всего времени. Каждые 1000 уникальных текстов сохраняются на диск, поэтому после остановки можно повторить ячейку. Обучение башен при прерывании начинается заново. Если вручную заменить локальные веса E5, нужно удалить её кэш.

## Проверка качества

На валидацию отложены 10% уникальных нормализованных текстов запросов. Один и тот же текст не попадает в обе части. Для метрики запросы различаются по всем пяти поисковым признакам.

Поиск при валидации точный, среди уникальных объявлений train. Это другой корпус, поэтому результат не равен оценке скрытого benchmark.

| Вариант | Recall@50 |
|---|---:|
| Исходная E5 | 0,1929 |
| После 1 эпохи | **0,2156** |
| После 2 эпох | 0,2147 |
| После 3 эпох | 0,2146 |

Для финальной модели выбрана одна эпоха обучения на всех парах. На первых 100 запросах benchmark HNSW нашёл 97,32% соседей из точного top-50. Это проверка индекса, а не метрика релевантности.

## Где результат

Готовый файл: `avito_retrieval/simple_artifacts/answer.csv`. В нём 2452 строки, по 50 уникальных item_id. Повторно обучать модель для отправки этого файла не нужно.

В той же папке находятся `encoder` — веса E5, `towers.pt` — обученные башни, `validation.csv` — метрики, `items.hnsw` — индекс, `item_ids.parquet` — идентификаторы объявлений и `cache` — сохранённые эмбеддинги.

Первый запуск скачивает E5, последующие используют локальные веса. Для воспроизведения без интернета нужны эти веса и заранее установленные зависимости. Точные версии библиотек можно сохранить командой `%pip freeze > environment.txt`.

Использованы [multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small), PyTorch, Sentence Transformers, NumPy, pandas, PyArrow и [hnswlib](https://github.com/nmslib/hnswlib).
